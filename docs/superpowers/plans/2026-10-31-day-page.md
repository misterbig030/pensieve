# Day Page Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the lesson page into the day page: a fixed task column on the left, the lesson centred on the right, and lessons written as numbered steps that point at the tasks.

**Architecture:** One pure module turns a leaf's Read and Do rows into an ordered list of tasks with stable, content-derived ids. The page and the generate action both build from it. The model sees short labels (T1, T2) and writes fenced `step` blocks. `generateDailyContent` rewrites those labels to task ids before the lesson is stored. The client splits a stored lesson into text and step parts, and renders step cards that share ticks with the task cards. Ticks live in `localStorage` per node.

**Tech Stack:** Next.js 16 App Router, React 19, Tailwind 4, react-markdown, Vitest (node env, components via `renderToStaticMarkup`).

**Spec:** `docs/superpowers/specs/2026-10-31-day-page-design.md`. Visual reference: `docs/mockups/day-page.html`, screens B1 and B2.

## Global Constraints

- The local `DATABASE_URL` is the production database. Never click Write/Rewrite lesson, Mark complete, Log session or any planning action on a real track while checking the page.
- Live checks run from this worktree on `localhost:3001`, started detached with `nohup`, in the user's Chrome in a fresh tab. Never use port 3000, and never reuse an existing tab.
- Headings that should be Caprasimo need `font-heading`. There is no base rule.
- Colours come from the existing tokens (`bg-neutral-100`, `bg-secondary`, `accent-*`, `accent-2-*`, `primary`). No new hex values.
- Lessons already stored render exactly as today when they contain no `step` fence.
- A step whose task can't be found is still shown as a card. It is never dropped.
- Ticks never reach the server and never count as progress.
- Tests: `npx vitest run <path>` for one file, `npm test` for the suite (1235 tests pass at the start). Run `npx tsc --noEmit` before each commit that touches types.

## Review Focus

1. **A plan revision after a lesson exists.** Read rows keep their key, but practice rows are re-inserted. A step must resolve to the same task, or show unlinked with the "tasks changed" note, and never point at another task. Task 1 pins the practice id against the row's position. Task 7 pins the note.
2. **The model writes a label that isn't on the list** (`T9`, `t2`, or blank). `t2` resolves case-insensitively. `T9` and blank become an unlinked card with no stale note (Tasks 2, 3).
3. **Two practice rows with the same content** (same source, no item, same task text). Their ids must differ, or one tick would tick both (Task 1).
4. **Storage that throws or holds junk** (private window, a hand-edited value). The page renders with no ticks and doesn't crash (Task 5).
5. **A step fence inside an old lesson's other code block, or a lesson with no fences at all.** The second renders byte-for-byte like today. The first is accepted as a known limit: the splitter only matches a fence at the start of a line (Task 2).

    - Review: `Review <taskTitle>`
    - Youtube: `Watch <taskTitle>`

### Task 2: Step blocks in a lesson

**Files:**
- Modify: `lib/schemas/dailyContent.ts`
- Create: `lib/lessonSteps.ts`

**Interfaces:**
- Produces:
  - `STEP_FENCE = "step"`, in `lib/schemas/dailyContent.ts` beside `ANSWERS_FENCE`.
  - `type LessonPart = { kind: "text"; markdown: string } | { kind: "step"; n: number; taskId: string | null; nth: number; minutes: number | null; body: string }`
    - `n` is 1-based across the lesson.
    - `nth` is the 0-based count of earlier steps with the same `taskId`.
  - `splitLesson(markdown: string): LessonPart[]`. A step is a fence whose opening line is exactly ```` ```step ```` (any case, trailing spaces allowed) at the start of a line, closed by the next line that is ```` ``` ````.
    - Leading `task: <value>` and `minutes: <int>` lines, in either order, are read off the body.
    - The rest, trimmed, is `body`. An empty `task:` gives `taskId: null`.
    - Text parts that are only whitespace are dropped.
    - A lesson with no step fence returns `[{ kind: "text", markdown }]` with the input unchanged.
  - `resolveStepTokens(markdown: string, ids: ReadonlyMap<string, string>): string`. Inside step fences only, rewrites each `task:` value through `ids`, matching the token case-insensitively. A value that isn't in the map becomes empty (`task:`). Everything else is untouched.
  - `stepKey(taskId: string, nth: number): string`, which returns `${taskId}@${nth}`.
  - `hasStaleSteps(parts: LessonPart[], taskIds: ReadonlySet<string>): boolean`. True when some step has a non-null `taskId` that isn't in the set.

### Task 5: Ticks

**Files:**
- Create: `lib/dayTicks.ts`, `components/pensieve/day/useDayTicks.ts`
- Test: `lib/dayTicks.test.ts`

**Interfaces:**
- Consumes: `stepKey` (Task 2).
- Produces:
  - `taskTicked(taskId: string, stepKeys: string[], ticks: ReadonlySet<string>): boolean`. With steps, it's true when all step keys are ticked. Without steps, it's `ticks.has(taskId)`.
  - `toggleTask(ticks, taskId, stepKeys): Set<string>`. If the task is ticked, it removes `taskId` and every step key; otherwise it adds them all.
  - `toggleStep(ticks, key): Set<string>`.
  - `doneCount(taskIds: string[], stepKeysOf: (id: string) => string[], ticks): number`.
  - `ticksKey(nodeId: string): string`, which returns `pensieve.dayTicks.${nodeId}`.
  - `readTicks(storage: Pick<Storage, "getItem"> | null, nodeId: string): Set<string>`. It returns an empty set when storage is null, throws, holds non-JSON or holds a non-array. It keeps only string entries.
  - `writeTicks(storage: Pick<Storage, "setItem"> | null, nodeId: string, ticks: ReadonlySet<string>): void`. It swallows errors.
  - `useDayTicks(nodeId: string): { ticks: Set<string>; set(next: Set<string>): void }`. It starts empty and loads in `useEffect`, so the server and first client render match. It writes on every `set`. It reads `window.localStorage` inside `try`.
